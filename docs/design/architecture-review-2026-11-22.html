Problem. The engine returns a prose string, so the adapter parses the same command again and infers what happened from snapshots and reply.startswith; a wording change can silently drop an event.

Solution. Engine.execute(actor, text) returns a typed CommandOutcome; both adapters shape the same outcome, and the v2 adapter stops parsing and diffing.

  • • One verb, one implementation
  • • Events stop depending on prose
  • • Tests assert outcomes
  • • Adapter shrinks to shaping

02 · durability seam

One durable mutation, not one store method per verb

Strong local-substitutable

src/mud/storage/store.py:105, 158, 173, 190, 207, 236 · src/mud/engine/core.py:819, 1073 · SPEC.md:58, 78

Before · verb-shaped store

→

put · get from · use mutate memory and never cross the seam. Restart restores the pre-container inventory.

After · one commit

Engine

records changed
locations + flags

→

WorldStore

place(item, at)
set(entity, flag)
Every verb writes once; a new verb cannot forget the store.

Problem. PlayerStore mirrors five verbs, so durability is opt-in per handler; put and get from change inventory without a write, and a restart loses that move (SPEC v2.1.1 inventory persistence).

Solution. The engine records the object locations and flags a command changed and calls one location-shaped commit(changes); the store no longer knows the command vocabulary.

  • • Durability stops depending on the verb
  • • put/get survive a restart
  • • Store interface shrinks
  • • One transaction per command

Strong in-process

Problem. The effective world is derived three times: the validator, seed, and loader each expand reciprocal exits and shared locks; geometry is validated three times and containment placement twice.   • • Validation travels with the world
  • • Adapter stops re-deriving

One key rule; display names stay a command convenience, not a primary key.

Problem. The running world is keyed by display name while the database and wire are keyed by authored id, so identity is re-derived in five modules, the adapter assigns instance_id during serialization, login linearly scans rooms, and duplicate display names silently overwrite.

Solution. The loader builds one WorldIndex — room id/name, object and NPC id, one key per entity; the engine, wanderer, adapter and server resolve through it, and display names remain a command convenience.

  • • One id derivation
  • • Login loses the scan
  • • Duplicate names stop colliding
  • • Lookup in one index
